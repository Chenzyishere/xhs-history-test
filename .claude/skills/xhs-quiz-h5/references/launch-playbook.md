# 部署与冷启动

## 一、部署路线

| 阶段 | 方案 | 特点 |
|---|---|---|
| 起步/内测 | GitHub Pages | 免费、免备案、5 分钟上线，国内速度一般 |
| 正式跑量 | 阿里云 OSS + CDN + 备案域名 | 国内秒开，需 1–2 周备案 |

代码不变，随时可迁。

### GitHub Pages 步骤

1. 建仓库（必须 **Public**，免费账号不支持私有仓库 Pages）
2. 上传 `index.html`、`css/`、`js/`、`README.md`（**保持目录结构**）
3. Settings → Pages → Source 选 `Deploy from a branch` → 分支 `main` → 目录 `/ (root)` → Save
4. 等 1–3 分钟，访问 `https://用户名.github.io/仓库名/`
5. **注意末尾的 `/` 和仓库名不能省**

### 常见 404 排查

按顺序查：

1. **Actions 标签**有没有 `pages build and deployment`
   - 黄圈 = 还在构建，等 3 分钟
   - 红叉 = 构建失败，点进去看报错
   - 没有这条记录 = Pages 没触发
2. **分支名对不对**：Code 页左上角显示 `main` 还是 `master`，Pages 里选的必须一致
3. **仓库是不是 Public**
4. **文件在不在根目录**：如果在一个子文件夹里，Pages 的 root 就找不到 `index.html`

### 绑自定义域名

Settings → Pages → Custom domain 填域名 → Save。

| 绑子域名（推荐） | 绑裸域 |
|---|---|
| 类型 `CNAME` | 类型 `A`，加 4 条 |
| 值 `用户名.github.io` | `185.199.108.153`<br>`185.199.109.153`<br>`185.199.110.153`<br>`185.199.111.153` |

DNS 生效后回来勾 **Enforce HTTPS**。

**以 GitHub 设置页显示的 IP 为准**，这组 IP 偶尔会变。

### push 认证踩坑

GitHub 早已禁用密码认证，必须用 Personal Access Token：

- 在**正确的账号下**生成（多账号电脑最容易错）
- 勾 `repo` 权限
- 报 `Permission to xxx denied to yyy` = 电脑记住了另一个账号的凭据
- 去 **Windows 凭据管理器 → Windows 凭据**，删掉所有 `git:https://github.com` 条目
- 或临时绕过：`git push https://用户名:TOKEN@github.com/用户名/仓库.git main`

## 二、交付与售后

### 发码

默认对接小红书「自动发货」，**不要人工逐单发码**。

1. `data.js` 里的 `unlock.shopCode` 就是店铺密码
2. 打开 `tools/generate-codes.html`，复制自动发货文案
3. 贴进商品后台的自动发货内容

两个商品用不同 `shopCode`。密码泄露了就改 `shopCode`，同步更新自动发货文案。

如果后台支持卡密库，再改用「一单一码」：同一工具可批量生成校验码导入。

### 客服 / 自动发货文案模板

```
https://你的域名
验证码：店铺密码

复制链接到浏览器打开，输入验证码即可开始
验证码不能有空格，不区分大小写
测试不限使用次数和时间
有任何问题请第一时间联系客服
晒图 + 10 字好评，送其他工具
```

四个要素：**链接、验证码、使用说明、好评返利**。

### 售后预防

- 虚拟商品退款和差评会直接拖垮店铺分
- 自动发货工具（阿奇索这类）提前配好
- 差评话术提前写好，第一时间响应

## 三、冷启动

### 先澄清：没有"养号"机制

官方没有这个功能。"每天刷半小时点赞评论"那套基本无用。

真正会出事的是**新号一上来就做营销动作**：批量关注、批量私信、笔记带微信/外链、短时间高频发布。这类会被判营销号限流。

"养号"的正确理解是：**别让系统把你识别成营销号**。

### 用老号还是新号

| 老号情况 | 判断 |
|---|---|
| 泛生活/情感/知识类，粉丝少，无违规 | 可以用 |
| 强垂类（美妆、穿搭、探店） | **新开**。标签改不过来 |
| 有违规或限流史 | **新开**。限流是账号级的 |

**默认建议新开专号**：这个品类吃垂直标签纯度，新号还有流量扶持期。别拿老号做实验。

### 新号基建

- 一机一号一卡，用常用手机，实名注册
- 不用模拟器、不多开、不接群控
- 头像干净，有"测试/文化"感
- 昵称带领域词，别写成营销号样式
- 简介说清"做什么、关注能得到什么"，**不出现任何联系方式**
- 兴趣标签选心理、历史、文化、测试

### 观察期（3 天）

只做三件事：

1. 每天正常刷 20–30 分钟同赛道内容
2. 点赞收藏 5–10 条同赛道笔记
3. 关注 5–10 个同赛道博主（别一天关注几十个）

**不发笔记、不发私信、不改简介联系方式。** 目的是让系统先定准标签画像。

### 首发内容

前 3–5 条纯内容，不带商品、不带联系方式。

三种封面先各测一条，看哪种起量：

| 类型 | 例子 | 作用 |
|---|---|---|
| 悬念型 | 做完这个测试，我不敢承认自己像他 | 拉点击 |
| 结果型 | 我是苏轼，你是李白还是嘉靖？ | 拉分享 |
| 痛点型 | 内耗的人，都测出了同一个历史人物 | 拉共鸣 |

节奏：**隔天一条**，别连发。每天固定 15 分钟回评论，回得像"人"。

### 店铺下来后

同一批素材直接挂商品，定价 1.9 先测，2.9 是备选。老笔记补挂"相关商品"。

## 四、要盯的三个数

| 指标 | 及格线 | 不达标怎么办 |
|---|---|---|
| 做题完成率 | > 70% | 题目太长或选项难选 |
| **保存/分享率** | **> 30%** | 结果文案不像"我"，改文案不改代码 |
| 笔记 → 商品点击率 | 边跑边看 | 封面和标题问题 |

分享率是最关键的数。它上不去，说明结果没写到人心里，回头改 `data.js` 的 `traits` 和 `tagline`。

---

## 五、合规红线

- 测试类虚拟商品在平台是敏感区，**不要说"算命""预测命运""封建迷信"**，往"人格匹配""文化趣味"上靠
- 历史人物配图**不要直接搬画家作品和博物馆图**（有侵权判例），用 AI 生成
- AI 生成内容要符合国内标识要求
- 笔记文字自己写或改写，不要直接贴 AI 原文（可能被标 AI 内容限流）

---

## 六、换算题的时机

一个题材跑通后（有稳定单量、分享率达标），再考虑：

1. 同一套代码换 `data.js` 出第二个题材
2. 第二个题材验证成功后，再上矩阵号
3. 矩阵阶段才需要批量素材工具（自动出大字报封面和结果截图）

**顺序不能反。** 单点没跑通就上矩阵，等于把没验证的东西放大。
